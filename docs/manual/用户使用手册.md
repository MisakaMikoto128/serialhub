# SerialHub 用户使用手册

适用版本: v1.6.1 · 有问题先查[故障排查 FAQ](#九故障排查-faq), 再到 [Issues](../../issues) 提问。


---

## 一、认识 SerialHub

SerialHub 是一个**串口 ⇄ WebSocket 桥接管理器**: 把串口设备变成一条 WebSocket 字节管道,
浏览器页面和脚本直接读写原始字节; 多座桥同时运行, 在一个网页管理台里建桥、启停、看状态。

**适用场景**

|场景 |说明 |
|---|---|
|浏览器上位机 |页面自带协议栈, 经 WS 直连串口设备 (无头浏览器无法授权 Web Serial, WS 管道是唯一通路) |
|自动化测试 |pytest/CI 里用脚本充当虚拟设备, 经 WS 与被测系统对发字节 |
|日常调试 |管理台随时看每座桥的状态与速率; 串口原始流在桥抽屉里只读旁看 |
|多人共用一台设备 |同一串口广播给所有客户端; 上行自动排队, 不会踩踏 |

**不是什么**

- **不是串口终端仿真器**: 不做 VT100/xterm 终端、不提供交互式输入行。「串口数据」页签
  只能**看**不能发 —— 发数据是客户端程序的职责 (网页或脚本经 WS 发)。
- **不做包帧协议**: `/ws` 只传原始二进制帧, 协议解析由页面侧自己完成。
- **不做 TLS 和鉴权** (v1.x): 只在可信网络使用, 见[安全须知](#十安全须知)。

## 二、安装

|方式 |步骤 |
|---|---|
|预编译包 (推荐) |从 [Releases](../../releases) 下载对应平台的压缩包, 解压即用。Windows 双击 `serialhub.exe` |
|cargo 安装 |`cargo install --path .` (在源码目录执行) |
|源码运行 |`cargo run --release -- --port COM1 --baud 115200` |

- Windows 桌面形态需要 WebView2 (Win10/11 系统自带); 不想装依赖就用 `--headless` 纯命令行模式。
- Linux/macOS 目前只保证可编译, 桌面形态需 webkit2gtk / WKWebView; 服务器脚本场景用 `--headless`。

## 三、五分钟上手

1. **启动**: 双击 `serialhub.exe` (或命令行 `serialhub`)。默认打开原生窗口,
   内嵌管理台, 网址 `http://127.0.0.1:8080`。
2. **建桥**: 点「新建桥」→ 串口下拉里选一个 (没有就点「扫描」) → 设波特率
   (默认 115200) 与串口参数 → 创建。数据端口已预填下一个空闲端口, 一般不用改。

   ![管理台仪表盘](../images/dashboard.png)
   ![新建桥](../images/create-bridge.png)
3. **连设备**: 点「启动」, 徽章变绿「运行中」即串口已打开。设备一侧插好线即可。
4. **网页看数据**: 点桥名打开抽屉, 切到「串口数据」页签只读旁看原始流
   (ASCII/HEX 可切); 程序接入则连 `ws://<桥网址>/ws` (网址显示在桥卡片上)。

到这里桥已在跑: 重启程序桥会自动恢复, 拔插串口会自动重连。

## 四、核心概念

|概念 |说明 |
|---|---|
|管理台网址 |程序自身监听的**固定地址** (默认 `127.0.0.1:8080`), 永远可达。提供网页管理台与 `/api` 管理接口。改它: CLI `--addr` 或界面里改后「应用」 |
|数据网址 |**每座桥自己的地址** (默认从 8101 起自动分配), 只跑一条 WS 二进制通道 `/ws`。程序接入连这里, 生命周期内端口不变 |
|桥 |一块串口 ⇄ 一个数据网址的映射。四种状态: 运行中(绿) / 连接中(绿闪) / 重连中(琥珀) / 已停止(灰) |
|客户端 |连到数据网址的 WebSocket 连接。收: 广播给所有客户端; 发: 排队串行写入串口。可限最大数量 (0 = 不限, 超限新连接被拒绝) |
|自动重连开关 |每桥独立, 默认**开**: 串口拔出/出错按 1s 节奏自动重试。关: 掉线直接变「已停止」不重试, 手动打开不受影响; 运行中改开关即时生效 |

一句话分清两个网址: **管理台网址管程序, 数据网址管字节。**

## 五、界面详解

### 仪表盘

主屏一行一座桥: 名称、串口、数据网址、状态徽章、速率火花线、连接数、运行时长、最近错误。
页头下方实时显示与当前配置**等价的启动命令**。全站复制动作都是图标钮:
点一下拷入剪贴板, 成功后旁边弹「已复制」气泡约 1.5s 自散。
页头「打开面板」在系统默认浏览器打开管理台; 「设置」换主题、改管理台网址。
右上「新建桥」建桥; 每行「启动/停止/设置/删除」管理该桥。

### 流程图与速率

每桥卡片内有流程图: **串口 ⇄ 桥 ⇄ 数据网址**, 有数据流动时线路点亮。
速率区每秒刷新: RX/TX 速率 (火花线) + 累计字节数。

![流程图与统计](../images/flow-stats.png)

### 桥抽屉 (三页签)

点桥名或「设置」打开:

|页签 |内容 |
|---|---|
|设置 |串口/波特率/参数/流控/最大客户端数/自动重连开关, 改完「应用」生效 |
|串口数据 |**只读旁看**串口原始流: ASCII/HEX 双视图、暂停/清空、自动滚动, 最多保留 5000 行 |
|统计 |累计收发字节、连接数、最近错误、运行时长 |

![桥抽屉](../images/bridge-drawer.png)

### 设置弹窗 (主题 + 管理台网址)

- **主题**: 下拉即换, 立刻生效不刷新页面, 记在本机。一个主题 = exe 旁 `themes/`
  目录 (CLI 可用 `--themes-dir` 改) 里的一个 .css 文件, 只管配色、圆角这类外观。
  内置四套 —— 浅色 (默认) / 深色 / 示例·奥利奥 / Windows 95 —— 首次启动自动写入;
  「示例·奥利奥」即自制示范, 照抄改配色就是新主题。
- **管理台网址**: 改完立即生效, 串口与各桥数据不受影响, 页面自动跳到新网址,
  重启后仍用新网址。

### 桌面客户端 (窗口与托盘)

- **关窗 = 退到后台**: 点窗口 X 只是隐藏, 桥继续收发; 左键点托盘图标恢复窗口, 终端历史原样保留。
- **托盘图标随状态变色**: 绿 = 运行中 / 琥珀 = 连接中·重连中 / 灰 = 已停止。
- **托盘菜单** (右键): 显示主窗口 / 在浏览器打开控制台 / 打开串口 / 关闭串口 / 退出。
  右键只弹菜单, 左键恢复窗口, 两键互不干扰。
- **退出程序三路**: 托盘菜单「退出」; 管理台页头「退出程序」(两段确认); 任务管理器兜底
  (不保证串口优雅释放)。前两种会先停串口、释放 COM 再退出。
- Win11 默认把新托盘图标收进溢出区 (`^` 展开), 可在任务栏设置里改为常显。

![系统托盘](../images/tray.png)

## 六、命令行参考

```bash
serialhub --port COM1 --baud 115200 --config 8N2 --addr 127.0.0.1:8080
serialhub --list-ports
serialhub --headless --port COM1          # 纯命令行模式 (脚本/CI)
```

|参数 |默认 |说明 |
|---|---|---|
|`--port <名称>` |无 |串口名, 如 `COM1` / `/dev/ttyUSB0`。不给 = 启动为未打开态, 由管理台驱动 |
|`--baud <数值>` |115200 |波特率, 110~2,000,000 |
|`--config <组合>` |8N2 |数据位/校验/停止位, 如 8N2、7E1、7O1 |
|`--flow <模式>` |none |流控: none / rtscts / xonxoff |
|`--max-clients <n>` |0 |每桥最大客户端数, 0 = 不限; 超限新连接被拒绝 |
|`--addr <ip:port>` |127.0.0.1:8080 |管理台监听地址。GUI 模式下界面里改会自动重启程序; headless 改地址需重启进程 |
|`--fleet <路径>` |`%APPDATA%\SerialHub\fleet.json` |桥清单文件, 变更即存, 重启自动恢复全部桥 |
|`--no-fleet` |— |关闭桥清单持久化 (本次运行不读不写) |
|`--headless` |— |纯 CLI 前台模式: 无窗口无托盘, Ctrl-C 或退出接口结束。脚本/CI 专用 |
|`--gui` |(默认) |原生窗口 + 托盘模式, 与 `--headless` 互斥 |
|`--no-open` |— |给了 `--port` 也不自动打开, 运行时用管理台「打开/关闭」 |
|`--list-ports` |— |列出本机串口后退出 |
|`--reconnect` / `--no-reconnect` |开 |串口断开自动重连 (每桥还可单独在界面里改) |
|`--themes-dir <路径>` |exe 旁 `themes/` |主题目录 (见「设置弹窗」), 不存在则启动时创建并写入内置主题 |

> 旧单桥用法 (`--port/--baud/...`) 仍然有效: 等价于自动建一座桥并启动。

> Windows 发布版无控制台黑窗 (GUI 子系统, 双击即用); 代价是 `--headless` 时 stdout
> 不回显到终端 —— 脚本判活走 `/api/status`, 需要控制台输出请用调试构建 (`cargo run`)。

## 七、程序接入

### 数据端点

每座桥一条: `ws://<数据网址>/ws` (推荐完整写法; 不带 `/ws` 的裸地址等价受理,
旧脚本不用改), **只传原始二进制帧**, 双向。用浏览器直接打开数据网址不会有网页,
只有一条接入提示。
收 = 串口收到的字节 (广播给所有客户端); 发 = 经队列串行写入串口。
控制面 (`/api/*`, JSON) 与数据面彻底分离。

三条铁律:

1. **只管字节, 不管协议**: 帧解析是页面侧的事。
2. **WS 消息边界 ≠ 串口帧边界**: 设备一次 `write` 可能被拆成多条消息, 多次 `write`
   可能被合并成一条。你的协议栈必须容忍任意分块 (按你的协议自己组帧)。
3. **慢客户端丢旧帧**: 下行缓冲 1024 条, 消费跟不上时丢最旧帧保连接 (Lagged) ——
   不反压、不踢人。高波特率 + 慢消费端 = 主动丢数据, 请确保消费端跟得上。

### Python 示例 (`pip install websockets`)

```python
import asyncio, websockets

async def main():
    async with websockets.connect("ws://127.0.0.1:8101/ws") as ws:
        await ws.send(b"\x01\x03\x00\x00")     # 上行: 写入串口
        while True:
            data = await ws.recv()             # 下行: 串口原始字节
            print(repr(data))

asyncio.run(main())
```

### JavaScript 示例 (浏览器)

```js
const ws = new WebSocket("ws://127.0.0.1:8101/ws");
ws.binaryType = "arraybuffer";
ws.onopen = () => ws.send(new Uint8Array([0x01, 0x03, 0x00, 0x00]));
ws.onmessage = (e) => console.log(new Uint8Array(e.data));   // 组帧自己做
```

### 最小示例 (`examples/`)

仓库 `examples/` 目录有两个**可直接跑**的最小接入示例。两者顶部都注明了
同一句话: **SerialHub 是原始字节管道 —— 串口的"值"的语义 (如 Modbus 寄存器) 由你的协议层负责**;
注释里还讲清了上面的三条铁律 (原始字节帧 / 消息边界≠串口帧边界 / 多客户端广播)。

- `examples/web-client.html` — 零依赖单文件, 双击即用:
  输入框填桥数据网址 → 连接 → 收到的字节按 HEX/ASCII 显示, 输入文本即原始字节发送;
- `examples/python-client.py` — `pip install websockets`
  后直接运行: 收到的字节打印 HEX, 每秒发一行 `ping`。

五步上手 (以本机 COM1↔COM2 虚拟对为例, 实测通过):

1. **起桥**: `serialhub --headless --port COM1 --baud 115200 --config 8N2 --addr 127.0.0.1:8089`,
   认准启动输出里的**数据端口** —— 管理台端口 ≠ 数据端口:
   `SerialHub 管理台就绪: http://127.0.0.1:8089` + `兼容桥 b1 (CLI) → 数据端口 127.0.0.1:8090`;
2. **开示例**: 双击打开 `examples/web-client.html`, 输入框填 `ws://127.0.0.1:8090/ws`, 点「连接」;
3. **对端灌数**: 接在 COM2 上的串口助手/脚本写几个字节 (如 `01 03 02 AB CD`);
4. **看收发**: 网页立即按 HEX/ASCII 显示收到的原始字节 (可顺带观察消息分块);
   在网页输入文本点「发送」, COM2 对端即刻收到;
5. **换 Python 客户端**: `python examples/python-client.py` —— 收打印 HEX、每秒发一行 `ping`;
   同时开两个客户端连同一座桥, 可看到同一条串口流广播给所有客户端。

实测截图见 [docs/team/reports/examples-demo/](../team/reports/examples-demo/)。

## 八、API 摘要

管理接口都在**管理台网址**下, JSON, POST 成功 `{"ok":true}`, 失败 400 + `{"ok":false,"error":"..."}`。

|方法 |路径 |作用 |
|---|---|---|
|GET |`/api/fleet` |桥列表 + 每桥统计 (桥对象 15 字段, 含 `retries`/`autoReconnect`) |
|POST |`/api/fleet` |新建桥 |
|GET |`/api/fleet/{id}` |桥详情 |
|POST |`/api/fleet/{id}/start` |启动 |
|POST |`/api/fleet/{id}/stop` |停止 |
|POST |`/api/fleet/{id}/config` |改配置 |
|POST |`/api/fleet/{id}/delete` |删除 |
|GET |`/api/fleet/{id}/tap` |WebSocket, 只读旁看该桥串口流 |
|GET |`/api/ports` |列本机串口 (全局可用) |
|POST |`/api/open-console` |在系统默认浏览器打开管理台 (桌面壳「打开面板」按钮走此端点) |
|POST |`/api/shutdown` |优雅退出整个程序 (管理台 + 全部桥) |
|GET |`/api/status` |单桥状态, 13 字段 (仅在恰好一座桥时可用) |
|POST |`/api/config` / `/api/open` / `/api/close` / `/api/restart` |旧单桥接口 (同上, 仅单桥模式) |

## 九、故障排查 FAQ

**Q: 启动报「端口被占用」?**
管理台网址 (`--addr`) 被其他程序占用才报错。若已有一个 SerialHub 在跑, 再启动会弹
「已在运行」提示 (含管理台网址), 确定后自动在浏览器打开管理台, 不算错误。
桥的数据网址冲突时, 程序会从 8101 起自动找下一个空闲端口。

**Q: 串口被别的程序占用, 桥打不开?**
关掉占用程序再「启动」。SerialHub 自己也会重试: 若开启了自动重连, 占用解除后会自动恢复。

**Q: 拔掉 USB 后会怎样? 插回来呢?**
开启了自动重连 (默认) 时: 徽章变「重连中」, 卡片显示「串口已断开，正在自动重连 (第 n 次)…」,
n 实时递增; 插回后数秒内自动回「运行中」, 弹「串口已恢复」横幅约 3s。
期间网页客户端**不掉线、零动作**, 恢复后数据自动续传。若关闭了该桥的自动重连,
掉线即「已停止」, 需手动「启动」。真机拔插 10 次演练步骤与验收口径见
[QA 拔插演练指南](../team/reports/qa-sprint5-plan.md)第 4 节。

**Q: 局域网另一台电脑打不开管理台?**
默认只监听 `127.0.0.1` (仅本机)。要让局域网访问, 把地址改成 `0.0.0.0:8080`, 并放行防火墙
入站规则。v1.x 无 TLS 无鉴权, 暴露到不可信网络风险自负, 见[安全须知](#十安全须知)。

**Q: 关窗后没看到「已退到系统托盘」气泡?**
系统的**勿扰/专注助手**可能把气泡吞了 —— 这是系统行为。没看到气泡不代表程序退出:
在任务栏托盘 (含 `^` 溢出区) 里找圆点图标, 左键点击恢复窗口。

**Q: 升级后主题外观没变?**
上次落盘的 `themes/<名>.css` 会遮蔽内置主题的更新。删掉旧 .css 再重启, 新版本会重新写入。

**Q: 不知道设备是哪个 COM 号?**
`Win+X → 设备管理器 → 端口 (COM 和 LPT)` 里看, 或运行 `serialhub --list-ports`,
或管理台建桥时点「扫描」。拔插一次 USB, 新出现的那个就是它。

## 十、安全须知

- **v1.x 没有 TLS, 没有鉴权**: 任何能连上管理台网址/数据网址的人都能读写字节、改配置、
  退出程序。**只在可信网络 (本机/内网) 使用, 勿暴露公网**, 暴露公网风险自负。
- 需要远程访问时, 建议走 SSH 隧道等自己加壳; TLS/鉴权在 v1 明确不做。
- 漏洞报告渠道: [SECURITY.md](../../SECURITY.md) (请勿在公开 Issues 里贴可利用细节)。
