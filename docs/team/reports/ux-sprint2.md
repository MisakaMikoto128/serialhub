- 测试人: 体验官 (UX 角色), 2026-09-12 · 背景: dev-sprint2.md / qa-sprint2.md 已读, 仍以用户姿态黑盒操作
- 环境: Windows 11 · 2560×1600 物理 · 系统 150% 缩放 · serialhub.exe (release, 双击式启动)
  `--port COM1 --addr 127.0.0.1:8080`; 数据源 COM2 pyserial 全双工 (1 行/s 文本 + 每 10s 二进制块);
  COM8 未触碰; 收工后 serialhub 全退、COM1/COM2/8080/8081 全部释放
- 方法说明: 原生窗口用 PIL ImageGrab 截屏 + Win32/UIA 自动化 (窗口移动/关闭、控件 Invoke、
  托盘坐标注入点击均做过命中验证); 注入点击与真人点击可能存在差异 —— 涉及托盘菜单/气泡的
  结论同时列入文末「人工 30 秒清单」请用户复核

## 总评

**桌面壳的"地基"打得非常正: 同一控制台 100% 复用、关窗退后台、桥在后台持续干活、恢复后历史全在、托盘三态变色实时正确 —— 但托盘右键菜单在我机器上无论如何呼不出 (五项含唯一优雅退出"退出"全部不可达), 加上 README 对新形态零说明, 现在还不能说"能当日常工具推荐"。** 修掉 P1-1/P1-3 (菜单可达性 + README) 并复核 P1-2 (气泡) 之后, 可以推荐: 日常当串口终端 + 后台桥用会很顺手。

## 反馈清单

### P0 阻塞

无。核心流程 (启动→窗口内收发→关窗后台→恢复→缩放→重启) 全部走得通。

### P1 难受

**P1-1 托盘右键菜单呼不出, 五项菜单整体不可达 (含唯一优雅退出)**
- 现象: 在 Win11 溢出区与提升到可见区两种位置、左键/右键两种操作下, 应用菜单均未出现
  (ux-sprint2/10-tray-leftclick.png、11-tray-menu.png、16-tray-menu-visible.png、18-burst-02.png); 右键后 120ms 间隔高速连拍 10 帧也无闪现 (18-burst-*)。左键行为是
  "恢复主窗口" (10/19), 不出菜单。三种注入方式 (mouse_event / SendInput / PostMessage) 结果一致。
- 为什么难受: 「在浏览器打开控制台」「打开/关闭串口」「退出」只能靠菜单; 尤其是"退出" ——
  用户想关掉程序只能开任务管理器杀进程, 这不是成熟产品的样子。
- 建议: 排查 tray-icon 菜单弹出路径 (经典坑: TrackPopupMenu 前必须 SetForegroundWindow,
  否则菜单不显示/即逝); 若确认是注入点击的局限, 请按文末人工清单复核后降级本条。
- ⚠ 本条同时进「人工 30 秒清单」第 1 项。

**P1-2 关窗后的"首次气泡"未出现**
- 现象: PostMessage WM_CLOSE 关窗后 8 秒内 20 帧连拍托盘区, 无任何气泡/Toast (ux-sprint2/06-balloon-02.png 等 20 帧)。
  本机 Win11 处于勿扰状态 (任务栏有铃铛标志), 系统="通知优先级"可能吞掉 Shell_NotifyIconW 气泡;
  Dev 报告称代码路径已执行。黑盒无法判定是"没发"还是"被吞"。
- 为什么难受: 首次关窗的用户看到窗口消失、无任何反馈, 会以为程序退出了; 与 Dev "不弹窗抢焦点"
  的克制设计叠加后, 反馈链条完全静默。
- 建议: ① 勿扰环境下气泡不可靠, 不应作为唯一反馈; ② 可考虑关窗时 tooltip 常显或窗口隐藏前
  无需任何动作的静默方案, 并在 README 写明"关窗=后台"; ③ 人工清单第 2 项复核 (暂时关闭勿扰再关窗)。

**P1-3 README 对桌面形态零说明 (文档未跟上默认行为变更)**
- 现象: README 中 grep `headless|gui|托盘|窗口|桌面` 零命中。按 README 快速开始启动, 用户预期的
  是"浏览器打开即用", 实际得到一个原生窗口 + 托盘 —— 行为变了, 文档没变; `--headless` 的存在
  与两者取舍 (QA 夹具用 headless / 日常用 GUI / headless 下端口被占的报错位置) 全靠读源报告才知道。
- 建议: README 补一节: 默认 GUI (窗口+托盘+关窗即后台)、`--headless` 何时用、托盘图标含义、
  退出的正确姿势 (托盘菜单或关窗?)。

### P2 锦上添花

**P2-1 GUI 模式「客户端」恒为 2 (WebView 双自连)**
- 现象: 无人连接时 UI 与 /api/status 均显示 clients=2 且 90 秒稳定不泄漏; netstat 显示桥进程自持
  4~5 条 TCP 连接 (含 2 条 WS)。对照: 浏览器打开同页 = clients=1; --headless = clients=0
  (反证 2 条 WS 都来自 GUI 壳/WebView)。
- 为什么难受: 多客户端广播是核心卖点, "客户端"这个头条指标在 GUI 下永远虚高 1, 外部真连了
  一台上位机时显示 3, 用户无从建立信任。
- 建议: 查 WebView 内页面的 WS 连接次数 (疑似重连未守卫或双重初始化), 或壳层不计入自身。

**P2-2 托盘 tooltip 的辅助文本随相位累积拼接**
- 现象: UIA 读溢出区图标 Name = `"SerialHub · COM1 · closed SerialHub · COM1 · open"` —
  closed 与 open 两段拼在一起 (ux-sprint2/11-tray-menu.png 前后对比); 而实际悬停 tooltip 显示正确 (21 右下角
  "SerialHub · COM1 · open")。
- 为什么难受: 屏幕阅读器用户会听到自相矛盾的状态; 也暴露 set_tooltip 更新路径可能在壳层
  重复注册。
- 建议: 相位变化时复用同一托盘项更新 tooltip, 而不是累积。

**P2-3 托盘图标默认埋在溢出区 + 图标观感**
- 现象: 首次启动图标在 Win11 溢出飞出区 (ux-sprint2/08-tray-overflow.png), 悬停 5.5 秒无 tooltip; 提升到可见区后 tooltip
  约 3 秒出现。图标为程序画的圆点, 5 倍放大边缘发虚 (ux-sprint2/20-dot-gray-closed.png、20-dot-amber-retry.png、20-dot-green-open-again.png)。
- 为什么难受: 首次使用者关窗后任务栏找不到任何痕迹 (气泡又没显示), 容易以为程序没了;
  圆点无轮廓、在浅色任务栏上对比度一般。
- 建议: README 指引"在任务栏设置里把 SerialHub 提为可见"; 圆点加一圈描边或换成
  带字母的方块, 小尺寸更清晰。

**P2-4 启动失败对"双击用户"完全静默 (Dev 已自报 P2, UX 侧确认其影响面)**
- 现象: 端口被占时 GUI 在创建窗口前 stderr + exit(1) (QA 已验证); 双击场景无控制台,
  用户看到的是"双击了但什么都没发生"。
- 建议: 维持 Dev 的方向 (托盘气泡兜底), 或至少 stderr 之外写一行日志文件。

### 惊喜点 (请保持)

- **双击式启动体验干净利落**: 无黑控制台残留、秒出窗口、自动按 CLI 参数开串口、终端立刻收数
  (ux-sprint2/01-first-launch-fullscreen.png、23-restart-clean.png)。
- **同一控制台真·零差异**: 窗口内发文本 `hello from window` 17B、HEX `DE AD BE EF` 4B 到 COM2
  均字节级正确 (与 Sprint 1 浏览器版同精度); 布局/交互与浏览器一致, 无"套壳感"。
- **关窗 = 退后台是真的**: 桥在窗口隐藏期间持续工作 (rxBytes 从 53k 涨到 116k), 托盘左键一键
  恢复, 恢复后 1187 行终端历史与 HEX 视图状态原样保留 (ux-sprint2/21-restored-history.png) —— 这套"后台常驻"语义完整正确。
- **托盘三态变色实时且正确**: closed=灰 / retry=琥珀 / open=绿 (ux-sprint2/20-dot-gray-closed.png、20-dot-amber-retry.png、20-dot-green-open-again.png), 用 HTTP 驱动相位切换
  跟手无迟滞, 与状态机/UI-3 配色一脉相承。
- **tooltip 文案符合心智**: `SerialHub · COM1 · open` 一眼看懂端口+状态 (21 右下角)。
- **左键托盘 = 恢复主窗口**: 符合 Windows 托盘应用惯例 (无需进菜单找"显示主窗口")。
- **--headless 退化干净**: 无窗口无托盘 (EnumWindows 0 个, 无新托盘注册), clients=0,
  未给 --port 时正确处于未打开态 —— 与 GUI 是同一个数据面, 切换无心智负担。
- **Sprint 1 的两处终端硬伤已修复**: 每行被劈成 "1B+85B" 两帧的显示撕裂消失了 (ux-sprint2/02-window-terminal-feed.png 行完整);
  二进制 0x80+ 不再显示乱码字形, 统一 `·` 占位; 行计数恢复真实 (1 行/s ≈ 1 行计)。
  时间戳开关补上了 (Sprint 1 P1-6), ASCII/HEX 视图都生效 (ux-sprint2/04-ts-on.png)。
- **缩放与 DPI**: 窗口拖到 720×700 物理 (150% DPI 下等效极窄) 单列自适应、无横向滚动、无破版
  (ux-sprint2/22-window-720.png); 150% 缩放下文字渲染清晰。
- **退出干净**: 强杀后 COM1 立即可重开、8080/8081 释放、再起秒级恢复无残留 (ux-sprint2/23-restart-clean.png)。
