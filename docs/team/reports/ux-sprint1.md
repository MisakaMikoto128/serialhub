## 总评

**骨架和工程素质超出预期 —— 自愈、重试、上限、禁用说明这些"看不见的功课"全做对了, 但终端区显示层有一个系统性缺陷 (每条记录被劈成两行) 让"当一个好看的串口终端用"这句承诺打了折扣。** 当前状态: 推荐给只把它当"WS 字节管道"的同事 (不看终端区) —— 可以; 推荐当日常串口终端 —— 还不行, 修掉 P1-1~P1-5 后可以放心推荐。按 spec §8 验收口径 (UX 无 P0/P1), 本轮 **P0 = 0、P1 = 6**, P0 全绿暂不达成。

## 反馈清单

### P0 阻塞

无。核心流程 (打开→收发→改参→重试→恢复) 全部走得通, 未发现崩溃/panic/卡死。

### P1 难受

**P1-1 每条接收记录都被劈成两行, 终端可读性系统性受损**
- 现象: 每行数据的**首字节**恒定单独成行 —— 文本行显示为孤行 `+[` + 内容行; "BURST" 行显示为 `+B` + `+URST 000391 …` (ux-sprint1/03-terminal-ascii.png、08-burst-100lps.png)。原始 WS 抓帧证实桥侧把一行 (87B) 拆成 1B (`5B`) + 85B 两帧发出, 前端再按帧边界断行。连带后果: 行计数翻倍 (100 行/s 实显 ~200 行/s), 5000 行有效历史缩半。
- 为什么难受: 设备以任意分包到达是串口常态 (NMEA/Modbus 设备从不保证一次 write 一行), 用户会以为数据被破坏或设备发错; "好看的终端"第一眼就显破。
- 建议 (二选一即可): ① 桥端合并短读 (读到 `\n` 或空闲窗口再广播); ② 前端跨帧拼接"未完行", 仅在 `\n` 处断行。

**P1-2 HEX 视图折行把一个字节劈成两半**
- 现象: 长行折行处出现 `… 30 31 3` / `2 33 …`、`FF 80 7` / `F 03 04` —— 一个字节的前后半分居两行 (ux-sprint1/07-hex-bytesplit.png)。
- 为什么难受: HEX 视图是看协议帧的, 劈半字节会直接看错数值。
- 建议: 按字节边界折行 (等宽布局下按"N 字节/行"手动分行, 或禁用 break-all 类样式)。

**P1-3 非法输入静默拒绝, 无任何反馈**
- 现象: ① HEX 模式发送 `XYZ1`: 不发送、无提示, 输入框原样留着 (ux-sprint1/10-send-hex-invalid.png); ② 关闭态波特率填 `50` 或 `3000000` 点「打 开」: 无反应、无红框、无横幅 (HTML min/max 校验存在但只在表单提交语义下才显示) (ux-sprint1/25-baud-invalid.png)。
- 为什么难受: 用户不知道是"没点上"还是"被拒了", 只能反复试; 这类小哑炮最消耗对工具的信任。
- 建议: 校验失败就地提示 (红字/toast), 数字输入用 `input.reportValidity()`, HEX 用一条"无法解析为字节: XYZ1"。

**P1-4 二进制字节在 ASCII 视图显示为原始乱码字形**
- 现象: 0x00–0x1F 渲染为 `·` (这个对), 但 0x7F/0x80–0xFF 直接输出成 `�`/`Uޭ` 等乱码字符混在行内。
- 为什么难受: 看起来像终端坏了/编码错了, 而不是"这里是不可打印字节"; 与 `·` 的既有约定也不一致。
- 建议: 非可打印 ASCII 一律 `·` 或 `\xHH` 记法, 保持每字节等宽。

**P1-5 宽屏布局下计数器数值被截断**
- 现象: 1440 宽度下 RX 字节显示 `656,9…`、运行显示 `0:30:…` (ux-sprint1/02-conn-panel-zoom.png、16-retry-state.png); 讽刺的是 720 窄屏因改为两列反而完整显示 (ux-sprint1/19-narrow-720-full.png)。
- 为什么难受: RX 字节数是联调时最常盯的数字, 长时间运行值永远看不全。
- 建议: 计数卡 `min-width` 或数值列自适应, 最多缩小字号, 不要省略号。

**P1-6 功能缺口: spec UI-4 的"时间戳可选"未实现**
- 现象: 终端工具栏只有 ASCII/HEX/暂停滚动/清空, 无时间戳开关。
- 为什么难受: spec P0 范围内明确列了此项; 排障时靠设备侧时间戳, 自己加的字符没有时间戳不好对时序。(若"可选"意为"可不做", 建议 spec 改措辞并同步 backlog。)

### P2 锦上添花

**P2-1 HEX 模式 TX 回显不可读**: 回显 `>●●●●` (ux-sprint1/10-send-hex-invalid.png), 认不出发的是 `DE AD BE EF`。回显设计本身是好的 (见惊喜点), HEX 模式建议回显十六进制原文。

**P2-2 HEX 行首 "+/=" 前缀无图例**: 实际含义是"未完行/完整行", 页面无说明; 若 P1-1 修复, 未完行几乎不再出现, 建议直接去掉或加 tooltip。

**P2-3 Retry 态串口下拉显示不一致**: 重试 COM99 时下拉显示 `COM1` (COM99 不在选项中, 回退首项), 与下方错误横幅矛盾 (ux-sprint1/16-retry-state.png)。建议显示 status 里的端口原文或"COM99 (不存在)"。

**P2-4 「追加换行 \n」对 HEX 模式无效但复选框仍可勾选**: 实测 HEX 发送未追加 0A, 无任何说明。建议 HEX 模式下禁用该框并注明"仅文本模式"。

**P2-5 端口选项文案重复**: `COM8 — USB-SERIAL CH340 (COM8)` 尾部再重复一次 COM8, 建议去重。

**P2-6 客户端只有数字无明细**: 想知道"还有谁连着" (IP/来源/连接时间) 做不到。共享实验室场景里这个信息有实用价值; 页脚"勿暴露到不可信网络"的提醒配一个来源列表会更可感知。

**P2-7 「打开中」态实际不可观测**: 本机打开 <100ms, 徽章直接 已关闭→已打开, 四态只见三态, "绿闪"无从验证。无需修复, 验收注明即可。

### 惊喜点 (请保持)

- **照 README 一条命令即用**: 启动秒级, 首开无控制台报错, 参数 (115200/8N2) 与 CLI 完全一致, "开箱即所见" (ux-sprint1/01-first-open-1440.png)。
- **暂停滚动 = 缓冲重放, 不丢数据**: 暂停期间发的 `PAUSE_MARKER` 恢复后完整出现; 这是专业终端才有的正确语义。小 nit: 暂停时行计数仍在涨, 与"屏上内容冻结"略有歧义, 可加"缓冲 N 行"提示。
- **5000 行上限真实生效**: 突发至 5000 后 DOM 节点封顶不再涨, 内存不膨胀; 高频 100 行/s 下页面基本跟手 (最大帧间隙 83ms, 平均 17.3ms), 无卡死无崩页。
- **坏端口演练体验完整**: COM99 打开 → 徽章转琥珀「重试中」+ 红色横幅给出中文系统错误 ("打开 COM99 失败: 系统找不到指定的文件。"), Retry 态点「关 闭」可跳出, 换回 COM1 一键恢复 (ux-sprint1/14/16/17)。
- **WS 断开自愈**: 强制断开页面 WS → 徽章「WS 未连接」→ 约 3.5s 自动重连、数据恢复, 全程无需刷新 (ux-sprint1/22/23)。
- **所见即所开**: 关闭态改 9600/8N1 → 打开 → UI 与 `/api/status` 一致 (ux-sprint1/13-reopen-9600-8n1.png)。
- **TX 字节精确、二进制完好**: 逐次发送的字节数与计数器核对无误, `DE AD BE EF` 原样到达对端。
- **发送区禁用带原因**: 关闭态下提示"串口未打开, 发送区禁用" —— 恰是 UI-5 要的"禁用态明确" (ux-sprint1/11-closed-state.png)。
- **适配性过关**: 720×700 单列布局无破版、无横向滚动、发送流程可走通; 135% DPI 两档 (1440@1.35、1067×667@1.35) 无重叠无裁切 (ux-sprint1/19/20/21)。
- **细节**: 多客户端计数实时 (1→2→1); 键盘焦点环可见、回车即发送; 波特率框悬停有 `110 ~ 2000000` 范围提示; 页脚一句话讲清协议 (原始二进制 /ws、TX 先到先发) 与安全边界。

## 摘要 (≤10 行)

1. 首开即用、参数与 CLI 一致、无报错, 第一印象好。
2. 系统性缺陷 P1-1: 桥把一行拆成 1+N 两帧、终端按帧断行, 每条记录劈成两行, 行计数翻倍。
3. HEX 视图折行劈半字节 (P1-2), 看协议帧会看错数。
4. 非法 HEX / 越界波特率静默拒绝无提示 (P1-3), 信任杀手。
5. 二进制 0x80+ 显示为乱码字形 (P1-4), 应统一受控占位符。
6. 宽屏计数器截断 (P1-5), 窄屏反而正常; 时间戳开关缺位 (P1-6)。
7. 状态机徽章绿/灰/琥珀三态到位, Opening 态过快不可观测; COM99 重试与逃生路径完整。
8. WS 断开 3.5s 自愈、暂停不丢数据、5000 行封顶、TX 字节精确 —— 工程底子扎实。
9. 720 窄屏与 135% DPI 均无破版, 多客户端计数实时。
10. 结论: 修完 P1-1~P1-5 可放心推荐当日常终端; 当前可先推荐给纯"WS 管道"用途的同事。
