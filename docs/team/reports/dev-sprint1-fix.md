## NEW-1 修复轮 (QA 复验回流的渲染层缺陷) — 2026-09-12 第二次追加

### 现象 (qa-sprint1-fix.md NEW-1)

无换行连续二进制流下终端内容重复渲染 (~2×)、内嵌 0x0A 断行丢失、carry 乱序; CDP 证明 WS 帧
100% 到达浏览器、无 JS 异常, 定界在 ui/index.html 的 20ms 合并/carry 逻辑。

### 根因

旧实现的合并层用 **rxQueue / rxQueued / carry 三个分离状态**手工拼接: 每窗 flush 把
"carry ++ queue" 重建大缓冲, 再扫 `\n`、再对剩余做 512B 强制切分、再把新尾巴拷回 carry ——
多真相源结构, 任何中间态扰动 (emitLine 循环中途异常、清屏/复位与 flush 交叠、过期定时器)
都没有守恒保证: 异常路径会在 `rxQueue=[]` 之后丢弃 buf 尾部 (丢字节+断行丢失),
carry 每窗整段重拼无代次防护 (重放/跳过窗口), 行边界落在任意偏移上 (QA 观察到的
"乱序/重复"在行级视角与这种切碎不可区分)。

复现与定界过程 (诚实记录): 用带 `SEQnnnnn|` 序号标记的灌数器 + 浏览器端"拼接全量扫描"
(把 entries 按序拼回字节流再扫序号) 复测旧实现, 稳态字节流本身守恒 (0 重复 0 乱序),
QA 的 ~2× 在我方速率/分块下未复现; 但旧结构的守恒是"巧合可过"而非"可证", 且确凿存在
上述异常路径缺陷 —— 按工单要求直接重构, 同时把定界工具交给 QA。

### 修法 (ui/index.html 渲染层, 单一 flush 路径状态机)

1. **唯一缓冲**: `rxBuf = [未完行前缀][新帧...]` 单真相源, 删除 rxQueue/rxQueued/carry 三状态;
   `onRxFrames` 只做 append, 不碰任何行状态。
2. **定时器唯一出缓冲路径**: 只有 `setTimeout(flushLines, 20)` 出缓冲; 调度时代次 `rxGen++`,
   回调持代次执行, `gen !== rxGen` 直接丢弃 (过期定时器双保险, 工单的"拿到代次才 flush")。
3. **交换式出缓冲**: flush 先 `buf = rxBuf; rxBuf = EMPTY` 整段交换, 扫 `\n` 断行、
   尾部 ≥512B 强制切分; 不足 512B 的未完行 **放回 rxBuf 头部** —— carry 只被后续帧追加
   (append-only), 同一字节要么渲染恰好一次、要么滞留为 carry, 结构上不可能重放/重复。
4. **QA 观测口**: 新增 `window.__sh = {frames, bytesIn, bytesOut, linesOut}`,
   守恒式 `bytesOut + carry = bytesIn ≈ /api/status.rxBytes`, 三层 (WS 进 / 出缓冲 / 渲染)
   任一不守恒可立即定界到具体层。

### 自验证据 (COM1 起桥 + COM2 灌数 + 浏览器 eval 读缓冲统计, 各流独立复位)

灌数器每 256B (文本 87B) 内嵌 `SEQnnnnn|` 单调序号; 校验 = entries 按序拼接后全量扫序号:

| 流 (30s) | 灌入 written | 桥 rxΔ | WS 进 bytesIn | 渲染 outB | carry | 序号扫描 |
|---|---|---|---|---|---|---|
| ① 带 \n 文本行 | 85782 | 85782 | 85782 | 85869* | 87 | 0..985 连续, dis=0, **dup=0**, 行数 986=灌入行数 |
| ② 无 \n 纯二进制 | 252160 | 252160 | 252160 | 251904 | 256 | 0..983 连续, dis=0, **dup=0**, 行长恰 512B |
| ③ 二进制偶含 0x0A | 252160 | 252160 | 252160 | 251904 | 256 | 0..983 连续, dis=0, **dup=0**, 246 个内嵌 0x0A 全部正确断行 (lfInRender=0) |
| ④ jitter-mixed 20s (5~60ms 随机到达) | 155648 | 155648 | 155648 | 155648 | 0 | 0..607 连续, dis=0, **dup=0** |

\* 流① outB 比 bytesIn 多 87 = 上一轮遗留 carry (1 条未完行) 在本轮正确出账, 逐字节对账闭合;
   outB 与 entryBytes 之差 986 = 被消费的 \n 分隔符字节数, 亦精确闭合。
- 三种流下 **written = rxΔ = bytesIn** 全等 (WS 层零丢失), **outB + carry = inB** 全等
  (渲染层零丢失零重复), 序号严格单调连续 (零乱序), 内嵌 0x0A 零丢失。
- 回归: 流① 主流程行数 1:1 保持; `cargo build` 0 警告; `cargo test` **21/21 全绿**;
  后端/数据面/`/api/status` 契约零改动。
- 测试后桥/灌数器/浏览器全部退出, COM8 未碰。
