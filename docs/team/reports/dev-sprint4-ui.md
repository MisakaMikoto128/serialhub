## 3. 契约使用与假设 (SPEC-QUESTION, 请架构师裁定)

- **SQ-UI-1**: `GET /api/fleet` 桥对象**无 maxClients 回显字段**。设置页「同时连接上限」现缺回显数据源 (按 0 显示); 若每桥上限存在, 请后端在 fleet 列表回显, 否则每次保存都会以上限 0 覆盖原值 —— FIX-17 同类静默降级风险。UI 已做 `typeof b.maxClients === "number"` 防御, 有字段即回显。
- **SQ-UI-2**: `POST /api/fleet/<id>/config` 未列于派工契约, 按 spec FR-10g 使用; body 复用 create 形状 + `maxClients`。形状不符请 dev-backend 反馈, 改动集中在一处 (`saveCfg`)。
- **SQ-UI-3**: 保守策略 —— 桥非「已停止」态锁定串口参数/网址/上限编辑 (热改属 spec 非目标), 仅名称可改。UX N7「应用后串口重连一下约 1 秒」剧本需后端支持运行中改配后再启用。
- **SQ-UI-4**: 串口数据页仅在页签激活时连 /tap (省流控防多桥内存膨胀), 切桥清空该页历史。若 QA 要跨页签持续旁看, 改动小。
- **SQ-UI-5**: 等价命令按 FR-10h 单桥映射 (`--addr` = 桥 listen); fleet CLI 若有 `--name/--fleet` 形态, 待契约后更新。
- **1013 挂接点**: 管理台页面不占数据面连接名额, 该文案在 tap 通道被 1013 关闭时显示; 常态由「同时连接上限」的 hint 承担预告。

### DEF-2 (P1) 卡片速率恒 0 —— 根因在后端列表缺字段, UI 侧验证正确 + 加固

- **根因定位**: UI 的速率绑定 (`updateCard` → `fmtRate(b.rxRate)`, 500ms 轮询原位刷新) 自始正确; `fleet_list` 与 `fleet_detail` 共用 `detail_json`, 列表必然含速率。DEF-2 的机制是 **QA 跑的构建里 fleet 列表尚未接速率** (dev-sprint4-backend.md 迭代注记「速率入详情」), UI 拿不到 `rxRate` 字段 → `fmtRate(undefined)` 渲染成伪造的「0 B/s」。dev-backend 17:01 重建后字段已入列表。
- **真后端复验** (8080 + CLI 桥 COM1, COM2 pyserial 灌 512B/100ms): Playwright 每秒采样 8 次, 卡片收速率 8/8 跟随 API 跳动 (4.9~5.5 kB/s vs API 5028~5554), 两条收方向线段点亮, 火花线出现形状 (采样点数递增 + y 值多样); 数字证据见 `12-real-traffic-rates.png`。FR-10c「每秒刷新」真实生效。
- **UI 侧加固 (防同类复发)**: 新增 `fmtRateField` —— 速率字段**缺失**时显示「—」而非伪造「0 B/s」, 契约回退从此一眼可见, 不再制造"统计引擎坏了"的假象。抽屉统计页同措辞。
- **附注**: 后端现在回显 `maxClients` (SQ-UI-1 解除, 设置页自动回显); fleet.json 持久化恢复实测通过 (重启后桥自动回来)。
