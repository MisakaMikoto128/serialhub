## 1. P1 (建议下个迭代修)

### P1-1 两段确认的「确认态」在鼠标悬停下完全不可读
- 现象: 录像行「删除」首点后按钮变空粉红块, 「确认删除?」文字不可见 (用户刚点完首点, 指针必然还在钮上)。
- 根因 (computed 实测): 悬停时 `button.danger:hover:not(:disabled)` 特异性 (0,3,1) 压过 `button.danger.armed` (0,2,1), background 被换成 `--err-bg`=#fae9e7, 与 color (同 --err-bg) 同色; border 仍是 --err。`ui/index.html` L183-185。键盘 focus 路径 (非 hover) 显示正常红底, 但鼠标路径是主路径。
- 波及面: 录像行删除、桥卡片删除、设置弹窗「替换导入」(class danger + armed 同族; `quit-btn.armed` 因 hover 规则带 `--err-ink` 不受累)。
- 证据: `06-rec-del-armed-1280-light.png` / `06b-del-armed-zoom.png` / `06c-armed-live.png` (computed: bg=color=#fae9e7, border=#bb3a30)。
- 建议 (仅供 dev 参考): armed 规则加 hover 守卫, 如 `button.danger.armed, button.danger.armed:hover:not(:disabled){background:var(--err);color:var(--err-bg)}`。

### P1-2 回放状态与后端真实状态脱钩 (replay/stop 未接入)
- 后端 ADR-24⑥ 已交付 `/api/fleet/<id>/replay/stop` + fleet 对象 `replay` 状态字段; UI 侧两者均未消费 (全文件 0 引用)。实测: 后端 `replay/stop` 成功后, UI 状态行仍显示「正在回放 … 循环开着」不收敛 (`05-rec-replay-after-backend-stop.png`); 循环回放在 UI 没有任何停止入口 (dev 报告 §5-Q2 当时的担忧, 后端已补, UI 未跟上)。
- 非循环回放的「按时长/倍速自动收点」工作正常 (实测 PASS)。
- 建议: 抽屉轮询时按 `b.replay` 字段驱动状态行, 录像行/状态行加「停止回放」钮走 replay/stop。

### P1-3 浅色主题灰字对比度 3.01:1 (WCAG AA 不达)
- 12px 正文灰字对抽屉/页面背景 3.01:1 (AA 需 4.5): `.rec-hint` (录制说明, 新)、`#recCount`「录像 (2)」(新)、`.send-hint` ×3 (含新转发 hint)、「命令行写法」hint 2.83:1。深色主题仅 equiv hint 4.41:1 边缘 (P2)。
- 深色全达标 → 病根是浅色 `--muted` 系令牌在 panel 底上偏浅。
- 证据: 断言输出 + `13-fwd-connected-1280-light.png` (转发 hint 目视偏浅可感)。

## 4. 惊喜点
- **「不谎报」哲学落地到位**: 录制中后端未回填时明说「帧数字节在停止后统计」, 回填后即时跟随 — 比硬凑实时数字诚实。
- **F3「保存并启动」时态按钮**: 保存钮文案随时态切换 (保 存/保存并启动), 停止态保存绝不偷跑启动, 语义闭环。
- **键盘细节**: 循环开关用视觉隐藏 input + `:focus-visible` 轨道描边 (标准可访问开关模式); 页签 role=tab/aria-selected/tabpanel 全套; Esc 关抽屉正常路径可用。
- **危险操作文案全程大白话 + 预告后果**: 替换导入警告框文案与播报逐字对上; 两段确认 3s 自动复原零失误 (多轮重复实测)。
- 四主题切换 marker 法实测零刷新, 深浅奥利奥 win95 控件样式全跟随, 无半主题残留在案。
