## 0. 设计立场 (先于一切线框)

用户已定性: 这是**桥接管理器**, 不是串口助手。落到界面上是三条铁律:

1. **主语是「桥」不是「串口」**: 主屏回答的唯一问题是「我的桥都还好吗」。串口、网址、网页都是桥的属性, 不再占据首屏第一行。
2. **只说用户看得见的事**: 界面上允许出现的名词只有 — 串口、网址、网页、程序、桥、连接。禁止出现: 重启、换绑、监听/侦听、WS/WebSocket、TCP、帧、契约、端点、广播、管道、客户端、实例、headless、原始二进制、错误码 (1013 等)、内部编号 (FR-x/ADR-x/UI-x)。
3. **每个动作自带后果预告**: 危险操作 (删除桥 / 退出程序 / 换管理台网址) 一律两段确认 + 大白话预告, 且必须包含一句「什么不受影响」的定心丸。

两种「网址」必须从词面上分开 (这是多桥模型最容易混淆的点):

| 界面词 | 内部对应 | 用户心智 |
|---|---|---|
| **管理台网址** | 控制面 (FR-10a) | 「我打开的这个页面在哪个网址」 |
| **数据网址** | 每桥数据端口 (FR-10a/g) | 「发给上位机网页去连的网址, 一座桥一个」 |

说明: `ws://127.0.0.1:9001/ws` 这类**要复制给别人的网址字符串是数据不是文案**, 原样展示 (如同 http://); 但一切**解释它的文字**不得提 WS。

## 1. 管理台信息架构

### 1.1 三层总览

```
主屏 (仪表盘)  ——  我的桥, 一行一座, 三秒看完全部健康度
   └─ 桥行 (×N) ——  流程图 + 徽章 + 速率 + 连接数 + 启停/删
        └─ 每桥抽屉 (右滑) —— 设置 / 串口数据 / 统计, 三页签
全局件: 顶栏 (品牌 + 管理台网址 + 新建桥 + 退出) · 异常横幅 · 空状态
```

| 区域 | 元素 | 说明 |

### 1.3 桥行 (一行一座桥) 元素清单

| # | 元素 | 规则 |
|---|---|---|
| 1 | 四态徽章 | UI-3 配色不变, 文字改小白词 (见 §1.7 词表); 琥珀「重连中」悬浮给出白话解释 |
| 2 | 桥名 (串口号 · 设备描述) | 桥名用户可改, 默认用串口号; 「COM3 · CH340」帮小白认设备 |
| 3 | 流程图 串口⇄桥⇄网页 | 三节点两线; **有流量线点亮并流动, 无流量灰虚线** (FR-10d); 左节点显示串口号, 右节点显示「网页 ×N」, 一座桥都没连时显示「还没有网页连接」 |
| 4 | 速率 收/发 | 每秒刷新 (FR-10c); 措辞「收 / 发」站在网页视角: 收 = 设备→网页, 发 = 网页→设备, 与流程图方向互为图例 |
| 5 | 火花线 | 近 60 秒「收」方向, 每秒一点; 静止灰, 有流量点亮 |
| 6 | 连接数 | 「已连接 2 / 不限」或「/ 上限 4」(FR-9b) |
| 7 | [启动] 或 [停止] | 按徽章互斥显示; 单击即生效, 不做确认 (可逆, 非危险) |
| 8 | [删除] | 红描边; 两段确认 + 后果预告 (可删后重建, 串口不受影响) |
| 9 | 错误行 (仅出错时) | 琥珀小字一行白话, 如「串口被别的程序占用中…」; 无错不占位 |
| 10 | 整行可点 | 点行任意处 (按钮除外) 打开抽屉 |

**设置页元素清单**: 串口选择+扫描 / 波特率 / 数据位·校验·停止位 / 流控 / 连接上限 / 数据网址 (默认自动分配, 端口号) / 桥名 / 折叠的「命令行写法」(FR-9c, 移入抽屉且收起 — 对小白是噪声, 对脚本党一次点开) / [应用修改]。
应用修改的提示分两行, 第二行仅在网址被改动时出现: 「网址改了: 已连的网页要改用新网址重新连 (串口不受影响)。」— 这是 FR-10f 端点稳定的诚实边界: 客户端不认识新端口号, 不许诺自动跟随。

```
                                          │ 【串口数据】   只看不动 · 原样显示       │
                                          │ [ASCII|HEX] [暂停滚动] [时间戳] [清空]   │
                                          │                             321 / 5000  │
                                          │ ┌──────────────────────────────────────┐│
                                          │ │ 09:12:03.114  Hello 0x01·0x02·…      ││
                                          │ │ 09:12:03.402  OK                     ││
                                          │ └──────────────────────────────────────┘│
                                          │  这里只是旁看; 想发数据请用连在这座桥上  │
                                          │  的网页/程序。                          │
```

**串口数据页** (FR-10e, 内部名 tap/侦听, 界面词定为「串口数据」): 工具条四钮 + 行数上限全保留 (UI-4), 无发送区; 底部一句固定提示讲清「只看不发」, 顺手告诉用户发送去哪了。

```
                                          │ 【统计】                                │
                                          │   收到   123,456 B   12.3 KB/s  ▂▅▇…   │
                                          │   发出     1,024 B    0 B/s    ▁▁▂…    │
                                          │   已连接  2 个 / 不限   历史最高 3      │
                                          │   已运行  3:24:11                      │
                                          │   上次出错  无                          │
```

**统计页元素清单** (FR-10c): 累计收/发字节 (自动 B/KB/MB) + 当前速率 + 大火花线 / 当前连接 (含上限) + 历史最高 / 本次运行时长 / 上次出错 (白话翻译为主, 原始错误文本折叠在「详情」里供报障) / 桥的数据网址 (再给一次复制 — 统计页是「把网址发给别人」最常被想起的地方)。

### 1.5 全局件: 换管理台网址 (原「地址块」的新家)

低频高级操作, 从首屏第一行降级进顶栏 [设置] 对话框; 文案按用户钦定口径: **换网址 → 本页自动跟过去 → 串口不受影响**。

```
        ┌───────────────── 管理台网址 ──────────────────────┐
        │  现在是  127.0.0.1:8080                           │
        │  换成    [ 127.0.0.1:8090 ]                       │
        │                                                   │
        │  [ 换网址 ]            ← 第一段                   │
        │  提示: 点「换网址」后还会在这里再确认一次。        │
        │                                                   │
        │  (第二段, 按钮变红)  [ 确认换网址? ]              │
        │  确认后: 本页自动跳到新网址, 不用做任何事;         │
        │  所有桥照常工作, 串口和已连的网页都不受影响。      │
        └───────────────────────────────────────────────────┘
```

进行中反馈: 「正在换网址…」→「新网址已生效, 正在带你过去…」(原地换绑, 页面自动跟随; 不再出现「重启中」「旧实例退出中」)。注: 「桥和网页都不受影响」建立在 FR-10a 每桥独立端口之上, 已列入 §4 交 QA 验证的断言。

### 1.7 状态词表 (四态徽章, UI-3 配色不动)

| 机器相位 | 颜色 | 现文案 | 新文案 | 悬浮白话 (琥珀/灰必配) |
|---|---|---|---|---|
| open | 绿 | 已打开 | **运行中** | 串口连着, 数据正常走 |
| opening | 绿闪 | 打开中 | **连接中** | 正在连接串口 |
| retry | 琥珀 | 重试中 | **重连中** | 串口暂时不在 (拔了或被别的程序占用)。插回设备就会自动接上, 不用操作 |
| closed | 灰 | 已关闭 | **已停止** | 这座桥没在跑。点「启动」开始 |

命名逻辑: 用户判断的不是「串口句柄的相位」而是「这座桥在不在干活」; 「已关闭」改成「已停止」避免「什么被关了」的疑惑。

## 2. 全站文案表 (逐条审定)

规则: 每条 [现文案 → 新文案 → 为什么]。处置标记: **必改** (题目点名/违 UI-0) · 改写 · 移除 · 保留。所有 title 悬浮同样视为用户可见文本, 一并审。

### 2.1 必改清单 (题目点名 6 处, 优先落地)

| # | 位置 | 现文案 | 新文案 | 为什么 |
|---|---|---|---|---|
| M1 | 地址块 label | `地址` | **管理台网址** | 多桥后「地址」一词歧义 (每座桥也有网址); 「网址」在 UI-0 白名单里 |

| M5 | 表单 label+hint | `客户端上限` / `0 = 不限; 超限的新连接以 close 1013 拒绝 (FR-9b)` | **连接上限** / `最多几个网页或程序同时连这座桥; 填 0 = 不限` | 「客户端」是商业黑话, 用户感知的是「连上来的网页」; `close 1013`、`(FR-9b)` 是实现词与内部编号, title 里也不许 |
| M6 | 拒连横幅/错误 | `WS 被拒: 已达最大客户端数 (1013), 发送不可用` 及 `连接被拒: 已达到最大客户端数 (1013)` | **没连上: 这座桥的连接已满 (上限 N 个)。关掉一个已连的网页, 或把「连接上限」调大。** | WS/1013 全是禁词; 错误必须给下一步动作 (goal-ux 既有结论)。新 IA 下出现于: 桥统计「上次出错」+ 被拒网页自身横幅 |
| M7 | 统计卡 | `客户端` | **已连接** (值 `2 个`, 悬浮: 连在这座桥上的网页或程序数量) | 同 M5; 桥行与抽屉统计用同一词, 不制造第二套说法 |
| M8 | 页脚 | `SerialHub · 原始二进制 WS 管道 (/ws) · 多客户端广播, TX 先到先发 · 勿暴露到不可信网络` | **`SerialHub · 串口桥接管理器 · 桥的配置自动保存, 关掉再打开会原样恢复 · 没有密码保护, 请只在自家电脑或内网使用`** | 原句五个实现词连击 (WS/管道/广播/TX/客户端), 小白零收益; 安全提示必须保留 (spec 非目标: 无 TLS/鉴权); 补持久化安心话术 (FR-10b) 回答「我关了桥还在吗」 |
| M9 | 顶栏徽章 | `WS 未连接` / `WS 已连接` | **正常时: 不显示任何徽章; 异常时横幅: `页面刷新中断, 正在自动重连…` (恢复自动消失)** | 正常状态不需要常驻徽章 (平静界面); 「未连接」会让小白以为软件坏了; WS 禁词。若 Dev 倾向保留常驻件, 退让文案: `刷新正常` / `刷新中断, 自动重连中` |

## 3. 新手剧本 (零文档走通验证)

每步格式: **看到什么 → 做什么 → 应看到什么**。全程只依赖界面文字, 无需 README。

### 剧本一: 建一座桥, 连上设备

| 步 | 看到 | 做 | 应看到 |
|---|---|---|---|
| 1 | 主屏空状态: 「还没有桥 — 一座桥 = 一个串口 + 一个网址…」 | 点 [＋ 新建第一座桥] | 弹出「新建一座桥」表单 |
| 2 | 串口下拉写着 `点「扫描」找串口` | 点 [扫描] | 下拉列出本机串口, 带设备名 (如 `COM3 — USB-SERIAL CH340`); 选设备对应的那个 |
| 3 | 波特率已填 115200, 参数行 8/N/2 | 按设备手册改波特率 (框旁有常用值), 参数照手册 | 输入合法时无红字; 非法数字立刻红字提示并给例子 (P6) |
| 4 | 底注「创建后这座桥立刻开始连接串口。」 | 点 [创建并启动] | 表单关闭, 列表出现新行 |
| 5 | 新行徽章 **连接中** (绿闪) | 什么都不用做 | 一两秒内变 **运行中** (绿), 流程图串口侧线点亮流动, 「收」开始出数字 |
| 6 (分支) | 徽章 **重连中** (琥珀) | 按悬浮白话处理: 插回设备 / 关掉占用程序 | 设备恢复后自动变回运行中, 全程不用点任何按钮 |

判定: 全程出现的词只有 桥/串口/网址/扫描/启动, 每个按钮自带后果; ✅ 零文档。

### 剧本二: 两个网页同时看一个串口

| 步 | 看到 | 做 | 应看到 |
|---|---|---|---|
| 1 | 目标桥行: 徽章 **运行中** | 点行 (或抽屉头) [复制] 数据网址 | 剪贴板得到 `ws://127.0.0.1:9001/ws` |
| 2 | 上位机网页的连接框 | 粘贴网址, 连接 | 桥行「已连接 1」, 右节点变「网页 ×1」 |
| 3 | 第二个网页 | 粘贴同一网址, 连接 | 桥行「已连接 2 / 不限」, 「网页 ×2」; 两个网页同时看到相同数据流 |
| 4 (分支) | 第二个网页弹 `没连上: 这座桥的连接已满 (上限 N 个)…` (M6) | 按提示二选一: 关掉一个已连网页; 或开抽屉把「连接上限」改大, 点 [应用修改] | 桥行错误行同步出现「有 1 个连接被拒 (连接已满)」; 处理后网页自动连上 |

判定: 「同时看」不需要任何概念解释 — 用户直接观察到 ×2 与两条同时滚动; 上限语义由错误文案自教。✅

### 剧本三: 改某座桥的波特率

| 步 | 看到 | 做 | 应看到 |
|---|---|---|---|
| 1 | 主屏按桥名/串口号找到目标行 | 点行任意处 | 右侧抽屉打开, 默认停在「设置」页 |
| 2 | 波特率输入框 | 改成新值 (如 9600) | 「应用修改」按钮高亮可点 |
| 3 | 按钮下方预先写着「应用后串口会重连一下 (约 1 秒), 已连的网页自动恢复, 不用操作。」 | 点 [应用修改] | 按钮短暂「正在应用…」, 徽章闪 **连接中** → 回到 **运行中** |
| 4 | 数据继续流动, 速率恢复 | (设备若需先断电改自身波特率, 用户去设备上操作) | 串口掉了会自动重连 (琥珀重连中 → 绿), 桥这边始终不用管 |

判定: 改参数 = 开抽屉 → 改数字 → 一个按钮; 后果预告先于动作出现。✅
